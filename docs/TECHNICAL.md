# Neon Player · 0.3.7

Полная отдельная Android-версия на **libmpv** с собственным интерфейсом. Lite 0.6.0 и Windows-плеер не изменены. Android 8.0+, телефон/планшет/Android TV. [Дорожная карта](ROADMAP.md).

## Что изменилось в 0.3.7

Шестерёнка во время просмотра открывает отдельные быстрые настройки: скорость, дорожки и пропуск → изображение → управление → «Все настройки». Выбор аудио/субтитров открывается напрямую. SponsorBlock показывается при наличии YouTube ID. С главной по-прежнему открывается полный список параметров.

## Базовые возможности

Выбранная тема **Deck** перенесена в главный экран, списки, файловый раздел и результаты поиска. Рендеры сохранены в [docs/design](docs/design/MENU-PROMPTS.md); это ориентиры, не скриншоты приложения. Реальные кадры продолжения берутся из доступного локального видео, когда Android может получить миниатюру; постеры к торрентам автоматически не загружаются.

В поиске каждый результат отделён карточкой: название, размер/сиды, трекер и кнопки «Смотреть» / «TorrServer». Есть сортировка и фильтры по трекеру/качеству в названии. Повторяющиеся одинаковые ссылки убираются. Списки используют виртуализацию, поэтому 500 результатов не создают 500 экранных карточек одновременно.

Сетевой раздел автоматически ищет SMB/TorrServer при запуске и открытии раздела, не блокируя интерфейс. Сохранён ручной ввод адреса, есть обновление результатов и кэш на сеанс для текущей сети. Проверяются loopback и собственный адрес Android: локальный TorrServer может находиться на том же устройстве. Это проверка стандартных портов, не универсальное обнаружение всех серверов на произвольных портах/подсетях.

Для недоступного локального TorrServer есть открытие установленного **ru.yourok.torrserve**. После возврата в Neon подключение повторяется. Сам TorrServe должен иметь установленный серверный модуль и локальную конфигурацию; приватные службы стороннего приложения Neon не запускает. Для адреса другого устройства запуск TorrServe не предлагается. Ошибки входа 401/403 не трактуются как остановленный сервер.

«Открыть файл» теперь ведёт в собственный файловый раздел: доступные папки с видео из индекса Android, число/размер файлов, сортировка, избранные папки и действия по удержанию. Android 14+ может предоставить доступ только к выбранным видео — тогда показываются только они. Конкретные папки можно дополнительно разрешить через «＋ Папка». Системный выбор отдельного файла сохранён как запасной вариант. Неиндексированные/скрытые каталоги автоматически не обнаруживаются.

## Начало

- Открыть файл системным диалогом либо прямой HTTP(S)/RTSP-поток. Дорожки, внешние локальные субтитры/звук и скорость доступны во время просмотра.
- Настройки → расположение: справа, слева, с двух сторон. Картинка сдвигается без обрезки; панели занимают свободные боковые полосы. Если их недостаточно, используется скрываемая нижняя панель поверх видео. Она не уменьшает кадр автоматически. Касание показывает/скрывает управление; на ходу оно скрывается через четыре секунды.
- Настройки → масштаб: **50–150%**, где 100% — вписывание целого кадра. >100% может обрезать изображение. Значение сохраняется отдельно по имени дисплея, ориентации и размеру доступного окна, с группировкой размеров по 40 dp. Это поддерживает отдельные профили сложенной/раскрытой раскладушки и планшета, а положение шарнира обрабатывается отдельно через WindowManager. TV использует центрирование.
- Ориентация по умолчанию **«По видео»**: широкий кадр — горизонтально, вертикальный — вертикально, включая поворот из метаданных файла. Кнопка поворота работает при выключенном системном автоповороте и меняет ориентацию для текущего файла; следующий снова следует выбранной политике. В настройках доступны также фиксированные режимы и системный режим. На Android TV принудительный телефонный поворот не применяется.
- Настройки → положение видео: вверх, вниз или центр. Значение хранится в экранном профиле. При верхнем положении кадр начинается у верхнего края окна, а управление располагается в свободной области снизу; при нижнем — сверху. Когда свободного места достаточно, там же показывается очередь серий. Масштаб не меняется автоматически, кадр не обрезается. Полосы, записанные внутри самого видео, этим сдвигом не удаляются. Видео рисуется до краёв экрана; интерактивные элементы учитывают системные безопасные области.
- Замок блокирует касания и обычную навигацию пульта. Для разблокировки удерживать замок пальцем или OK пульта. Аппаратная громкость остаётся доступна.
- Настройки → интерфейс: авто/телефон/TV. MENU пульта открывает настройки; F8 переключает телефон/TV. Когда панель скрыта, ←/→ перематывают, ↑/↓/OK возвращают панель. Медиа-кнопки работают отдельно.

## Плейлисты, папки и история

«Открыть папку» запрашивает доступ через системный диалог Android. Нажатие открывает папку или запускает файл с очередью соседних медиафайлов; удержание показывает действия. «Воспроизвести папку» запускает файлы текущего каталога в естественном порядке (1, 2, 10); вложенные каталоги открываются отдельно. У папок есть переход к родительскому каталогу внутри выбранного дерева.

В именованный плейлист можно добавить несколько файлов или папку. Папка хранится как ссылка и перечитывается при запуске плейлиста, поэтому новые серии не нужно добавлять вручную. Состав плейлиста можно изменять, название — менять. Файлы при удалении элементов/плейлиста не удаляются. Очередь доступна через кнопку списка в боковой панели либо «••• → Очередь / плейлисты»; есть предыдущий/следующий файл и автопереход после окончания. Новые функции не добавляют колонок поверх видео.

История хранится только локально, до 200 записей. Позиция записывается примерно раз в пять секунд и при выходе/смене файла. Повторное открытие предлагает продолжить или начать заново; у завершённых видео продолжение с конца не предлагается. Удержание записи открывает удаление, добавление в плейлист и передачу; историю можно очистить. `content://` передаётся другому приложению через системное «Поделиться» с разрешением чтения.

Эта итерация библиотеки работает с локальными файлами и обычными прямыми URL. Временные адреса сетевого моста, заголовки авторизации и SSH/SMB-пароли в неё не записываются; постоянные записи SMB/FTP/SFTP/TorrServer остаются отдельным пунктом roadmap. Для сетевых прямых URL срок жизни самой ссылки зависит от источника. Системные разрешения на файл/папку могут быть отозваны, а файл перемещён — тогда его нужно выбрать заново.

## Источники

**TorrServer:** указать HTTP(S)-адрес, при необходимости логин/пароль. Библиотека → торрент → файл → воспроизведение. Можно добавить magnet через «Прямая ссылка». Сервер должен работать отдельно; торрент-движка в APK нет. Первая сборка не показывает отдельный процент стартового буфера из API.

**Поиск:** по умолчанию `https://jac.red`. В настройках можно заменить адрес, выбрать Native/Jackett API и указать ключ. В результатах — название, размер, сиды и трекер. «Воспроизвести» добавляет торрент в настроенный TorrServer без сохранения в его постоянной библиотеке и ждёт метаданные; «Добавить» запрашивает сохранение в библиотеке. Даже вариант без сохранения создаёт временную запись на сервере, которая может остаться после просмотра. Автоматическое удаление чужих торрентов не выполняется. Если метаданные ещё не появились, открыть торрент позднее в библиотеке. HTTP 403 — ошибка сервиса, а не отсутствие результатов. Из текущего окружения сам jac.red отвечает 403, его успешная работа не заявляется.

**SMB:** хост, порт, общая папка, гость или логин/пароль/домен. Пустая общая папка запрашивает список. Короткое нажатие открывает каталог или медиафайл. Поддержка SMB2/3 зависит и от сервера; SMB1 не используется.

**FTP:** хост, порт, начальный путь; логин или anonymous, пассивный бинарный режим, UTF-8. Это обычный FTP без шифрования, не FTPS.

**SFTP:** SSH-сервер, порт, путь, логин/пароль. Первое подключение требует сверки и подтверждения SHA256-отпечатка ключа. Изменение ключа не принимается автоматически. Аутентификация приватным клиентским ключом пока не добавлена.

Сетевые файлы SMB/FTP/SFTP передаются libmpv через защищённый случайным токеном локальный HTTP byte-range мост на 127.0.0.1. Произвольный offset читается из источника без предварительного скачивания всего файла. Для FTP/SFTP новая HTTP-выборка может открыть новое соединение. Ошибка upstream закрывает текущий range вместо выдачи ложных данных.

Поиск LAN проверяет до 254 адресов непосредственно подключённой частной IPv4-подсети: SMB 445 и TorrServer 8090/8099/5665. Обнаружение FTP/SFTP и других подсетей пока не добавлено; адрес вводится вручную.

API-ключ поиска находится только в памяти. Сетевой пароль сохраняется только по галке: AES-GCM с ключом Android Keystore, без пароля в URI закрепа/истории. Без галки вход остаётся в памяти до закрытия приложения. Хосты, логины и SSH-отпечатки сохраняются локально. При изменении сервера/логина автоподставленный пароль очищается. Для получения SSID Android может требовать точное разрешение и включённую службу местоположения; при отказе доступны непривязанные закрепы и «Показать все». При HTTP TorrServer/поиске и обычном FTP транспорт не шифруется. Для TorrServer с Basic передаются заголовки текущего источника; при следующем файле они сбрасываются.

## Изображение

Подсветка полос: сияние от краёв или размытая сцена, яркость, размытие, мягкость границы. Отдельный низкоразмерный слой с захватом области видео через PixelCopy; mpv сохраняет исходную геометрию, слой заполняет только свободные области и выбранную мягкую границу. Изначальный экспериментальный shader-canvas больше не подключается. Это не весь набор временных эффектов ПК; режимы «Эхо» и «Зеркало» ещё не переносились. Подсветка ориентируется на геометрию кадра, не распознаёт чёрные полосы, записанные внутри самого видео.

Включены ПК-шейдеры и профили 480p/720p, RAVU, FSRCNNX 8/16 + KrigBilateral, SSimSuperRes, Anime4K A/B/C/A+A/B+B/C+A Fast/HQ. По умолчанию они выключены. Наличие цепочек не означает, что каждая подходит каждому мобильному GPU или будет работать в реальном времени. Сброс «Без шейдеров» восстанавливает обычное воспроизведение; подсветка отключается отдельно. Android/GLES требует проверки самих GLSL-файлов, а не только копирования их из Windows.

Используется gpu-next/OpenGL ES и попытка MediaCodec-copy с программным fallback. Это облегчает обработку изображения, но не обещает минимальное энергопотребление на всех устройствах. Windows LSFG/Lossless.dll не переносились. SBS/XREAL отложены.

## SponsorBlock

Включение, категории и привязка **текущего** видео к YouTube ID/ссылке доступны в настройках. Привязка не переносится на следующий файл. Автопропуск применяется только для подходящей длительности (известная длительность сегментов отличается не более чем на 2 секунды); пользователь должен выбрать ту же редакцию ролика. Одна вставка автоматически пропускается один раз за открытие файла, чтобы ручной возврат позволял её посмотреть.

Начиная с 0.3.6 отдельные видео YouTube / Shorts / live открываются через встроенный yt-dlp; нужны доступ к YouTube и публичное видео без входа. Обычные страницы остальных сайтов не разбираются. Для YouTube ID SponsorBlock определяется автоматически; для файла/прямого потока соответствующий ID можно указать вручную. Ошибка сети не должна мешать самому воспроизведению. API/данные SponsorBlock — [CC BY-NC-SA 4.0](https://github.com/ajayyy/SponsorBlock/wiki/Database-and-API-License), источник: [SponsorBlock](https://sponsor.ajay.app/).

## Сборка и исходники

JDK 17, Android SDK 35; Gradle Wrapper 8.11.1. `gradlew.bat :app:exportDebugApks` — сборка и экспорт в `dist/Neon-Player-<версия>-<ABI>.apk` вместе с SHA256. Версия берётся из Gradle, в интерфейсе показывается через BuildConfig. На этом Windows-хосте для обхода проблемы Java Unix-domain socket использовалось `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=Z:\neon-unix-sockets`. Это особенность окружения, не приложения.

Начальная подготовка native: скачать **официальный** `app-default-universal-debug.apk` релиза mpv-android 2026-09-17 в `vendor/mpv-android-2026-09-17.apk`, скачать исходники того же тега в `vendor/upstream/mpv-android-2026-09-17`, запустить `python bootstrap.py`. Скрипт проверяет SHA256 и извлекает .so, не подменяет пакет внутри стороннего APK. Текущий bootstrap также ссылается на расположение собственных Lite/ПК-исходников на рабочем компьютере — для переноса нужен соответствующий каталог либо настройка путей. Повторный bootstrap копирует исходные shaders, сохраняя дополнительные собственные файлы.

Native-движок не компилировался с нуля в этой итерации; он взят из проверенного по хешу официального артефакта. Kotlin/JNI-обвязка соответствует его тегу. Отдельные APK arm64-v8a, armeabi-v7a и x86_64 не требуют установки других приложений. Application ID `app.neon.player`, отдельно от Lite `neon.androidplayer`. Подпись отладочная для локальных тестов.
