# Проверка JacRed · Neon Player 0.3.8 / NeonTorr 0.1.0

Пример пользователя: https://jac.red/?s=kp178707 . Плеер запрашивает JSON `https://jac.red/api/v1.0/torrents?search=kp178707`, а не HTML-страницу поиска.

27 ноября 2026: и страница, и JSON endpoint возвращают из среды сборки HTTP403. Живые числа сидов/пиров этого запроса не подтверждены. Ошибка сервера показывается пользователю; она не подменяется пустым результатом или тестовыми записями.

Контракт сверен с исходниками jacred-fdb/jacred, commit 5680a312546f002fa5afba6f81b918f17f4dc721:
- Application/Search/TorrentQueryService.cs: Native API возвращает sid, pir, size (байты), createTime, updateTime, quality, relased, videotype, voices, seasons, tracker, title, magnet, url.
- Models/Details/TorrentBaseDetails.cs: sid — число сидов, pir — число пиров. Встречающийся в справочном JSON пример sid как идентификатора не соответствует этому контракту.
- Application/Search/JackettResultBuilder.cs: Seeders = sid, Peers = pir, PublishDate = createTime. Peers не пересчитывается вычитанием сидов.

Раньше основной плеер читал только seeders/Seeders и вообще терял pir, даты и прочую метаинформацию. Теперь поддерживаются оба формата. Неизвестное значение отображается «—», настоящий ноль остаётся нулём. Размер читается как Long, включая значения больше 2ГБ. Качество фильтруется по числовому полю, с резервным поиском в названии при отсутствии поля.

Из ответа принимаются до 2000 записей (ограничение upstream). Фильтр и сортировка применяются ко всему полученному набору; одновременно показаны первые 500 с явной подписью. Изменение сортировки пересчитывает эту выборку. Для последующих страниц серверного API этот клиент пагинацию не обещает.

Проверка JacRedContractTest выполняется на Android с реальным org.json: Native sid/pir, Jackett Seeders/Peers, null и 0, размер >2ГБ, метаданные, сортировка, нормализация ссылки Кинопоиска. Это проверка контракта, не живой доступности JacRed.
